# 今後の展望

このドキュメントは、現在のアプリの状態を確認したうえで整理した改善メモです。まだ一気に作り替える段階ではなく、実用性を上げながら少しずつ安全に育てる方針です。

## 現状評価

現在のアプリは、就活中によく発生する「予定をカレンダーに入れる」「メール文面を作る」「ES やメモを保存する」という作業を、1つの画面で扱える構成になっています。バックエンドなしで動き、依存も少ないため、プロトタイプとしては軽く扱いやすい状態です。

一方で、主要ロジックと画面コンポーネントが `src/App.jsx` に集まっているため、今後の機能追加では見通しが悪くなりやすいです。まずは機能単位でファイルを分け、抽出ロジックをテストしやすい形にするのが土台になります。

## 優先度高

1. 予定抽出ロジックの改善

   明示された年を保持する、複数候補日を検出する、年度またぎをより自然に扱う、日付の妥当性を確認する、会議 URL を優先して拾う、といった改善が必要です。

2. `App.jsx` の分割

   `ScheduleTab`、`MailTemplateTab`、`DocumentTab`、モーダル、toast、日付抽出ユーティリティを分けると、修正範囲が明確になります。最初は見た目を変えずに構造だけ分けるのがよさそうです。

3. 書類管理の UX 改善

   削除確認、検索、種別フィルター、並び替え、保存失敗時の通知を入れると、日常的に使いやすくなります。

4. localStorage データの扱い

   保存データの形式チェック、バージョン管理、インポート・エクスポート、容量超過時のエラーハンドリングを加えると安心です。

## 優先度中

1. メールテンプレートのカスタマイズ

   署名、氏名、大学名、企業名、担当者名などのプロフィール情報を差し込めるようにすると、コピー後の修正量を減らせます。テンプレート自体の追加・編集も将来的に有効です。

2. カレンダー出力の品質向上

   `.ics` の UID 追加、タイトル・場所のエスケープ、長文の折り返し、ファイル名の安全化などを行うと、外部カレンダーとの互換性が上がります。

3. アクセシビリティ

   モーダルの `role="dialog"`、フォーカス管理、Esc キーでの閉じる操作、アイコンボタンの `aria-label`、toast の読み上げ対応を入れると、操作の安定感が上がります。

4. UI 表現の整理

   現在使っている `animate-in` や `fade-in` は、標準の Tailwind 構成だけでは期待通りに効かない可能性があります。アニメーションを明示的に定義するか、不要なら取り除く方がよいです。

## 優先度低

1. データ同期・ログイン

   複数端末で使うには同期機能が必要ですが、個人情報を扱うため設計コストが上がります。まずはローカル完結のまま、エクスポート・インポートを整える方が現実的です。

2. テストの追加

   最初に効果が大きいのは、日時抽出ユーティリティの単体テストです。UI テストは、主要機能がもう少し固まってから追加するのがよさそうです。

3. Tailwind の更新

   開発依存の audit を厳密にゼロにしたい場合は Tailwind 4 系への移行が候補になります。ただし見た目や設定に影響が出る可能性があるため、単独タスクとして扱う方が安全です。

## 次の進め方

最初の一手としては、`App.jsx` の分割と日時抽出ロジックの移動をおすすめします。見た目を変えずに構造を整えたあと、抽出ロジックへテストを追加し、その上で複数候補日や会議 URL 優先などの精度改善を進める流れが堅実です。
